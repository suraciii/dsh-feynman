# Feynman research capability comparison, 2026-10-13

Baseline: dsh-feynman v0.21.3 (`85a801c`). Target: [Feynman v0.5.41](https://github.com/Companion-Inc/feynman/tree/17dfe0f87defa754ea915e834e9f401d292ae3d2), commit `17dfe0f87defa754ea915e834e9f401d292ae3d2`. This release covers upstream research features within DSH; provider, terminal and general session controls remain DSH-owned.

## Research parity

| Upstream capability | DSH implementation |
|---|---|
| Ten research workflows, including summarize | All ten plus the existing DSH review-loop dispatcher. Adapted upstream protocols preserve plan/evidence/final/provenance contracts, bibliography checks, quantitative evidence, revision and replication requirements. |
| Deep research continues after its plan (v0.5.38) | Continue immediately; pause only when the request explicitly asks to review the plan. |
| Source-on-disk summarization | Validated character-window controls, overlap, checkpointed notes, bounded concurrent or sequential chunks, source locations and explicit coverage gaps. |
| Scholarly database search | Vendored upstream clients for Semantic Scholar, OpenAlex, arXiv IDs, PubMed, Europe PMC, bioRxiv, medRxiv and Crossref; actual executable DSH tool, not just API-routing prose. |
| Exact scholarly modes | OpenAlex work/author/venue/citation/reference/semantic modes, arXiv explicit versions, PubMed metadata/conversion/related/citation/copyright/PMC routing, Europe PMC OA sections, preprint windows/categories/published links. |
| Request pacing, timeout and discovery fallback | Upstream pacers/retry/fallback implementations retained; DSH caller cancellation is forwarded through per-call fetch contexts. Exact lookup gaps remain explicit. |
| PubMed inline terms and affiliations (v0.5.29/.35) | Upstream XML parsers retained; fixture verifies BRCA1 inline text, multiple individual affiliations and consortium affiliation. |
| Hugging Face inspection | Three native tools for dataset metadata/schema/splits, file inventories and bounded text reads. Live credential refs resolve per call without changing global environment state. |
| AlphaXiv OAuth, refresh, search, full text, sections, Q&A, code and annotations | Pinned Alpha Hub 0.1.7 with upstream tool implementations. `/feynman alpha` supports login/callback/status/logout and research actions; account tool catalog refreshes after sign-in/status/logout. Local annotations remain without an account. |
| Document parse/search/screenshot | Adapted pi-docparser 4.0.0 using its pinned LiteParse 2.10.1. `feynman_fetch_content` stores the full parsed text, not the parser's preview. Native subprocess isolation, cancellation, page/DPI/OCR/password controls, output limits, saved artifacts and DSH image attachments. |
| Word documents without LibreOffice (v0.5.19) | Upstream paragraph extraction fallback with bounded input/inflate/preview, full extracted text saved on disk and explicit missing-layout/table/footnote/image caveats. |
| Four research agents | Complete researcher/writer/verifier/reviewer protocols exposed through a role tool, role catalog and run command; passed through native DSH subagent schemas. |
| Sixteen research skills | Bundled, prefixed DSH skill provider, with workflow-loader and command references adapted to DSH. No Pi CLI or agent alias is assumed. |
| Web search, fetch, stored content and code examples | Host web_search/web_fetch, `feynman_fetch_content` for PDFs/GitHub/multi-URL batches (host reader for HTML, direct status-checked retrieval as fallback), `feynman_search_content` paging (`offset`/`limit`) and search (`findText`), `feynman_source_check` for claim-level passage artifacts (CJK bigram matching, hashed file slugs), and existing code_search or a policy-aware host web-search bridge. Upstream `web_search` filters and the video/answer modes of `fetch_content` remain unimplemented; `fetch_content` now refuses private addresses. |
| Web curator | Per-session on/off command; a successful search adds a source-selection instruction before dependent fetch/synthesis. This is model-directed curation, not Pi's terminal picker. |
| Tool discovery and role discovery | `/feynman tools` reads the mounted tool schemas; `/feynman subagents` lists role protocols. |
| Project bootstrap, session logs and artifact browser | DSH queued workflows, preserved project instructions, durable logs (`log`, also loadable through `feynman_workflow`), and outputs/papers/experiments/notes browsing. `init` now writes the upstream templates deterministically (existing files kept), and `doctor` reports pandoc. |
| Research date, continuity and evidence integrity | Per-request UTC date, research system section, role/workflow rules, current task ledgers, numeric/artifact traceability, honest blocked/partial delivery and final-file checks. |
| Lean narrow work, reliable broad handoffs | Lead-owned narrow research; file-based role briefs and outputs, completed-result checks, failed-task accounting and ordered verifier/reviewer stages. No unsupported Pi workflow-script syntax. |

Default install mounts 15 plugin tools without AlphaXiv sign-in, and 19 with it when the host does not already provide code_search. Native web retrieval and delegation still use the host. The full command catalog is 12 workflows plus 15 session utilities; the skill catalog has 16 entries. `log` moved into the workflow catalog so `feynman_workflow` can load it.

## Removals and migration

Upstream v0.4.0 removed watch/jobs and PaperRank/paper access. v0.5.0–.4 removed or corrected model/preview/web-result commands and retired the session-search package; v0.5.31 cleans up old session-search installs.

| Removed local capability | Replacement |
|---|---|
| `rank` | `lit`/`deepresearch` with varied queries, foundational/citation-sorted plus recent/relevance evidence, explicit read-order rationale. |
| `paper` | Literature/full-text tools and `summarize` on a reachable source. |
| `watch`, `jobs` | DSH's own scheduling and job controls. |
| `preview` command | Research preview skill with available workspace renderers. |
| `feynman-model` | DSH's own model route settings. |
| `web-results` | Current `/feynman search` and the bounded stored-content tool. |
| Prior-session `search` behavior | Host session controls or the adapted transcript-search skill. The current command browses stored web and `feynman_fetch_content` results only. |

Existing research artifacts remain discoverable. `review-loop` stays as a DSH extension. Legacy AlphaXiv API-key configuration remains readable but is labeled as legacy; OAuth is the actual account path.

## Host boundary

Pi provider/model login, service-tier settings, terminal/keyboard/fullscreen behavior, package-management commands, native model retry/error UI, and general session creation/fork/quit controls are outside the selected research-parity scope. `/btw` and `thinking` preserve their documented DSH context semantics; they do not claim Pi's independent side-chat/provider runtime.

External network access and account permissions are prerequisites, not simulated capabilities. DSH tool-policy dispatch is preserved for AlphaXiv command actions and nested code search. Document paths, including symlinks and custom OCR data, are confined to the session workspace. Screenshots retain file references if the attachments seam is absent.

## Provenance and verification

`upstream.manifest.json` pins source versions, original file hashes and the upstream commit. `vendor/upstream/` and `vendor/docparser/` preserve source and licenses; the generated Node bundle ships with the package. Adapters handle DSH schemas, per-call secrets/signals, output redaction, image references and lifecycle disposal without installing Pi itself.

Tests exercise real Cordis/tool-runtime mounting, schema validation, local PDF parse/search/screenshots, workspace/symlink rejection, cancellation, credential redaction and refresh, OpenAlex/PubMed fixtures, role/skill loading, web-result reconstruction, source-curator behavior and retired-command rejection. Authenticated AlphaXiv provider calls require a real signed-in account and were not run as part of release validation.
